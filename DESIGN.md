# Design

## 1. Структуры данных и алгоритмы

### Структура проекта

- `src/core/` - основная игровая логика, чистые функции без DOM
- `src/storage/` - сохранения топ результатов в `localStorage`
- `src/ui/` - интерфейс
- `src/main.ts` - связь интерфейса и логики

### Состояние игры

```ts
type GameState = {
  settings: GameSettings;
  secret: string;
  history: HistoryEntry[];
  status: 'playing' | 'won';
  startedAt: number;
  finishedAt: number | null;
};
```

В `main.ts` хранится `GameState | null`, `null`- экран меню. Состояние не мутируется: `createGame` создаёт его, `submitGuess` возвращает новый объект и добавляет запись через `[...state.history, entry]`. Старое состояние не изменяется.

История попыток `history` - массив: так как нужен порядок попыток, массив перебирается при отрисовке, а повтор попытки проверяется через `some`. Объём данных маленький (1-20 записей), поэтому линейный поиск не будет мешать.

### `evaluateGuess(secret, guess) → { bulls, cows }`

Возвращает `{ bulls, cows }`. Оба параметра приводятся к нижнему регистру, так как для hex `a` и `A` - это одна и та же цифра.

- `bulls` - количество совпадающих позиций - символ `guess` совпадает с символом `secret` на том же индексе (`filter` с индексом).
- `cows` - количество общих цифр минус `bulls`. Общие цифры считает `filter` с `includes`. Формула будет верна, потому что цифры которые хранятся в `secret` уникальны: каждая общая цифра учитывается один раз, а bull уже входит в общие.

### `countPossibleSecrets(length, base)`

Считает число размещений без повторений P(base, length) = base! / (base − length)!.

- Реализовано через рекурсию `base * countPossibleSecrets(length - 1, base - 1)`,
- Первую цифру берет из `base`, остаётся тот же расчет, но для меньших чисел.
- Базовые случаи (`length === 0` вернет `1` - нейтральный элемент произведения, `length > base` вернет `0` - не хватает цифр),
- `memoize` хранит результаты в `Map` внутри замыкания. Ключ - пара `length,base`. Ключ из одного аргумента смешал бы разные системы счисления.

### `generateSecret(length, base, random)`

На каждом шаге берёт случайную цифру из оставшихся (с `random` задаёт индекс) и строит новый массив без этой цифры через `filter`, исходный массив не меняет. `random` передаётся параметром, поэтому в тестах результат один и тот же для одних и тех же данных.

### Типы данных

- `GameSettings` - `{ length: number; base: number }`, длина 2-6, основание 2, 8, 10 или 16.
- `HistoryEntry` - `GuessResult & { guess: string }`: результат сравнения плюс сама попытка.
- `RecordEntry` - запись рекорда: `length`, `base`, `attempts`, `timeMs`, `finishedAt`. Хранится в `localStorage` списком, отсортирован по попыткам, потом по времени.

## 2. Сложность (Big O)

### 2.1 `evaluateGuess` - `O(n*n)`

`secret` и `guess` - строки длиной `n`.

- Приведение к нижнему регистру и разбиение на массивы символов: по одному линейному проходу на каждую строку, O(n).
- `bulls`: один `filter` с индексом, сравнение символов на одной позиции стоит O(1), всего O(n).
- `commonDigits`: `filter` по `guessDigits` вызывает колбэк `n` раз, и в каждом `includes` перебирает до `n` элементов `secretDigits`. Вложенные операции перемножаются: O(n·n) = O(n*n).
- Итого O(n) + O(n) + O(n*n) = O(n*n): в сумме остаётся самое быстрорастущее слагаемое.
- Память: два массива символов, O(n).

`includes` можно заменить на `Set` и получить O(n), но при `n <= 6` нет выигрыша, а код с массивом проще читать. Поэтому оставлен массив.

### 2.2 `generateSecret` - `O(n*n)`

`n` - длина секрета (`length`),

`b` - основание системы счисления (`base`).

Всегда `n <= b`,
иначе `generateSecret` бросает `RangeError`.

- Построение алфавита (`Array.from`) делает `b` шагов: O(b).
- Рекурсия выполняет `n` шагов. На каждом `filter` копирует массив оставшихся цифр, его размер не больше `b`: O(b) на шаг.
- Итого O(b + n·b) = O(n*b). Так как `n <= b`, оценка сверху - O(b*b).
- Память: каждый шаг создаёт новый массив размером до `b`, а предыдущие остаются на стеке до конца рекурсии, поэтому O(n·b).

Для значений (`b <= 16`, `n <= 6`) это не больше сотни операций. Копирование массива на каждом шаге вместо мутации - цена за чистую функцию: исходный алфавит не меняется, и результат полностью определяется входом и `random`.

### 2.3 `isValidGuess` - `O(n)`

`n` - длина попытки `guess`.

- Приведение к нижнему регистру и разбиение на массив символов: один линейный проход, O(n).
- `hasRightLength`: сравнение двух чисел, O(1).
- `hasOnlyValidDigits`: `every` вызывает `isDigit` по одному разу на символ. Внутри `isDigit` - проверка длины строки и один `parseInt` на одном символе, это O(1), цикла по алфавиту там нет. Итого `n × O(1) = O(n)`.
- `hasNoRepeats`: построение `Set` из `n` символов, O(n), и чтение `size`, O(1).
- Проверки идут одна за другой, поэтому их стоимости складываются: O(n) + O(1) + O(n) + O(n) = O(n).
- Память: массив символов и `Set`, O(n).

Все три условия вычисляются заранее, поэтому функция не останавливается на первой неудаче. При `n <= 6` это не важно, а код читается как три именованных условия без вложенных `if`.

### 2.4 `countPossibleSecrets` - O(n) при первом вызове, O(1) при повторном

`n` - длина secret, `b` - base системы счисления.

- Рекурсия идёт цепочкой: каждый вызов делает одно умножение и один вызов себя с `(n - 1, b - 1)`.
  Ветвления нет, поэтому до базового случая `length === 0` выполняется `n` шагов по O(1). Итого O(n).
- `memoize` хранит результаты в `Map` с ключом `length,b`, а рекурсия вызывает уже мемоизированную версию. Поэтому после первого вызова в кэше лежит вся цепочка: `f(n, b)`, `f(n − 1, b − 1)`, ..., `f(0, b − n)`. Повторный вызов с теми же аргументами - одно чтение из `Map`, O(1).
- Кэш общий для всех вызовов, поэтому запрос с другими аргументами, который попадает в уже посчитанную цепочку, тоже дешевле.
- Память: кэш - до `n + 1` записей на одну цепочку, стек рекурсии - до `n` кадров, это O(n). Из меню можно выбрать не больше 20 сочетаний длины и системы счисления, цепочки при этом частично пересекаются, так что кэш остаётся маленьким.

Мемоизация здесь нужна для удешевления рекурсии: функция вызывается при каждом открытии настроек, а набор аргументов ограничен меню. Пересчитывать одну и ту же цепочку каждый раз незачем.
